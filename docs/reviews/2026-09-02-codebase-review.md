# Codebase review — 2026-09-02

Read-through of everything that changed since the previous review's fix commit (`8182349`,
"work the 2026-09-01 codebase review") up to `691bfe2` — the v0.1.0 release: commit context-menu
checkout / reset, graph column sized to the rows in view, remote branch folders and `merged`
badges, `MenuRef`, the light/dark toggle, Run git command… (backend `run_git` + argv / completions /
history / `CommandInput` / dock prompt), the commit lists' tree view, the full-window commit
dialog, and the workflows. Existing code was read where the new code leans on it (op runner,
`Menu`, `multiSelect`, `commitStore`), which is where two pre-existing defects surfaced (M4, L5).

Four independent passes (backend + CI · custom git command · grid + sidebar · commit panel +
dialogs + theme), findings merged and de-duplicated here. Every row was verified at the cited
line. Triaged and worked the same day: every row's outcome is in its **Decision** column (three
user choices — L6, L13, L25 — and one deferral, P1); frontend 292 / Rust 132 tests afterwards.

Not read: CSS beyond the rules the findings touch, `docs/design/*`, tests except to list gaps.

Severity: **M** = user-visible misbehaviour, real leak or a hang · **L** = edge case / polish ·
**P** = performance (no bug) · **H** = hygiene / tests / CI.

## Checked and fine (coverage record)

- `run_git` can only execute the configured git binary — `Command::new(git_path)`, no shell. Pager is off (stdout is a pipe), `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`, `GIT_OPTIONAL_LOCKS=0`, null stdin, op lock via `try_lock` → `Busy`, watcher suppressed, one `repo://changed`, Cancel kills the tree; `Refused` maps to `{kind:"refused"}`.
- `interactiveFlag` mirrors `check_custom_args` exactly (same sets, `--` cut-off, `--interactive` anywhere). `splitArgs` round-trips both `gitCmd` and `display_cmd` quoting; Windows backslashes literal; unterminated quote → error.
- `CommandInput`: Enter always `preventDefault`s (no double submit through the dialog form); Tab stops before the focus trap; Escape closes the list before the dialog sees it; listbox z-index 45 sits between the scrim (40) and BusyOverlay (50); scroll / resize listeners cleaned up. History dedup + cap 50; `load()` cannot race a push in practice.
- `commitMenu.ts`: upstream first, then same short name; detached HEAD handled; current branch excluded from checkout; `title` spread before `{...op}` so "Operation in progress" wins; Copy SHA stays enabled.
- `MenuRef` contrast on `--bg-elevated`: light ≈ 6.6:1 / 6.8:1, dark ≈ 7.7:1 / 7.3:1; hover / focus fall back to the item colour; the name stays inside the button's accessible name.
- `visibleLanes`: un-overscanned range, timer cleared on unmount and dep change, selector returns a number (no store writes on scroll), only a lanes change fans out to rows.
- Sidebar folder keys (`path` / `remote:<name>/<path>`) cannot collide (`:` is illegal in ref names); `aria-level`, `aria-expanded` correct; Remotes count unchanged.
- Working-tree double-click: mousedown selects first; the scrim blocks a second open; same busy guards as the panel; focus returns to the grid.
- Commit dialog: Enter in the summary → no-op submit; every button is `type="button"`; focus-trap edges are real tabbables; window minimum (900×600) fits the dialog's minimum (465×454); `.full` height resolves against the scrim; `autoFocus` on a `readOnly` input works; `commit()` returning `null` keeps the dialog open; a clean tree behind it just empties the lists; `useShortcuts` bails while any dialog is open; nested `react-resizable-panels` Groups need no id.
