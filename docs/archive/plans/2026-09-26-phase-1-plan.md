## Step 1 — build (the user keeps working)

The installed app can stay open: it runs from `%LOCALAPPDATA%\T4 Git UI`, the build writes
`target\release`.

The version override goes in a file, not inline JSON: inline quotes pass through bash and npm's `.cmd` shim,
either of which can strip them. Write `{"version":"0.10.11"}` to `<scratchpad>/version-0.10.11.json` (Write
tool), then from bash:

```sh
npm --prefix "F:/src/_ pet projects/t4-git-ui" run tauri -- build --no-bundle --config "<scratchpad>/version-0.10.11.json"
```

- Uppercase `F:/` (lowercase breaks vitest / vite). `--no-bundle` needs no signing env vars.
- Verify: `target\release\t4-git-ui.exe` exists and its file version
  (`(Get-Item <exe>).VersionInfo.FileVersion`) reads 0.10.11. `Cargo.lock` has `tauri-plugin-updater` 2.12.0
  (checked 2026-09-26).
- **The UI will still say 0.10.12.** The start screen and Settings' *is up to date* line read `package.json`
  (`StartScreen.tsx:190`, `SettingsDialog.tsx:147`), which the override does not touch. Only the updater's
  comparison sees 0.10.11. So no step below takes a version from the UI's text.

## Step 2 — back up, then the user closes the app

1. **While the installed app is still running** (on 2026-09-26: pid 51632, two windows, eleven tabs), copy
   `%APPDATA%\dev.topher.t4gitui` to the scratchpad. The backup comes first because closing windows one by one
   drops tabs from `layout.json`, and the backup is what gets restored.
2. Only then ask the user to close the installed app (every window), and confirm no `t4-git-ui.exe` is left
   (`tasklist`). It has to be closed: the local build shares its
   single-instance identity, so a running copy would take the launch, and the update's setup writes into its
   folder.
3. Check the fixtures under `c:/tmp/t4`: `work` (the two `topic/` folders, remotes `origin` / `mirror` /
   `nowhere`) and `dogfood`. Seed `layout.json` with those two windows (node, no BOM), as in the 2026-09-24
   walk.

## Step 3 — the updater walk (local 0.10.11 → published 0.10.12)

Proxy: `node docs/smoke/fixtures/throttle-proxy.mjs 8888 [bytesPerSecond]`, and the app launched with
`$env:HTTPS_PROXY` / `$env:HTTP_PROXY` = `http://127.0.0.1:8888` through
`pwsh -File docs/smoke/fixtures/smoke-launch.ps1` (the local build, isolated WebView2 profile, CDP 9222).
The build is `main`, so the UI is 0.10.12's (plain-words errors); only the updater underneath is new.

| # | Check | Pass |
|---|---|---|
| U1 | Launch with the proxy up | the launch check goes through the proxy (its log shows `github.com`, then the assets host); the badge *Version 0.10.12 is available — open Settings*; Settings › Updates **Update to 0.10.12…**. The offer is the proof, not the version text |
| U2 | Proxy stopped, **Check now** | *couldn't reach GitHub — check the connection (…)*; no toast, no *up to date* |
| U3 | A 60 s fetch from `slow` in `work`, **Update** in `dogfood` | refused with the running-operation reason; the fetch carries on |
| U4 | Proxy at 150000 B/s, **Update**, kill the proxy at a few % | *the download was interrupted — try again (…)*; bar gone; **Update** enabled; same process |
| U5 | Proxy at full speed, both windows open, **Update** | old pid gone, new one up within ~5 s with both windows; the new process's path is `%LOCALAPPDATA%\T4 Git UI\t4-git-ui.exe`, not `target\release` (`Get-Process t4-git-ui \| Select Id, Path`); that exe's file version is 0.10.12; the uninstall entry (`HKCU\…\Uninstall\T4 Git UI`) reads 0.10.12; **Check now** offers nothing. *Is up to date* alone proves nothing (it reads `package.json`) |

U5 is the one that matters: the download's minisign signature verified and the setup ran, under 2.12.0.
U2–U4 guard the error paths the plugin feeds. **Any fail: stop.** No tag until it is understood; the fallback
is pinning `tauri-plugin-updater = "=2.11.0"` and reverting #17's updater bump.

After U5 the running app is the installed 0.10.12. Close it (window ×, so `layout.json` is written) and stop
the proxy.

## Step 4 — the three smoke boxes

On the installed 0.10.12: `smoke-launch.ps1 -Installed` (CDP, isolated WebView2 profile), no proxy.

- **AI (`:1225`)**, over CDP in `work`: *Always collapsed* → expand `topic` (`topic/nested`, or
  `origin/topic/on-origin`) → **Fetch `origin` only** → it stays open. Not a plain Fetch: `work` also has
  `slow` (its upload-pack sleeps ~60 s, `c:/tmp/t4/slow-upload-pack.sh`) and `nowhere` (a missing path), which
  would stall or fail the fetch. Then `git -C c:/tmp/t4/work branch x/y` → the new `x` folder arrives
  collapsed.
- **AJ (`:1255`)**, the Remove-from-list third: with the app closed, add a recent whose path does not exist to
  `recents.json` (node, no BOM; the store is restored in Step 5 anyway). Launch, open it from the start screen
  → the failure toast with **Remove from list** → click it once: the recent goes, one toast closes once, no
  second removal or toast. (The native picker the box names was only a way to create a dead recent.)
  **Two buttons carry that label**: the toast's action (`StartScreen.tsx:73`) and every recent row's X
  (`StartScreen.tsx:269`). Scope the CDP selector to the toast; the box is about the toast's button.
- **DPI (`smoke-test.md:283`)**, the user by hand. Assumed at planning: no second monitor with another DPI
  (wrong — the walk used a real 150 % monitor, see the status), so with a repository
  open change *Settings › System › Display › Scale* (e.g. 100 % → 125 %) → the graph canvases stay crisp, not
  blurred or stretched; set it back. Claude can take a CDP screenshot at each scale for the record. **Record it
  as a substitute**: a scale change fires the same DPI change (`devicePixelRatio` moves), but it is not the
  box's literal drag to another monitor.
