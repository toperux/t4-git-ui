# Smoke group BS walk — the activity bar, the opening overlay from the click, 2026-10-09

Walks `docs/smoke/smoke-test-post-v1.md` group BS (plan `docs/plans/2026-10-09-activity-indicator-plan.md`). Step 0,
the gap measurement, ran before any code change; the rows follow, walked of `41884df` on Windows, Linux and macOS
over Remote Control, each session reporting back without ticking or committing. Every walked row passes on all
three; BS 2 isn't walked on Linux, as the row says. macOS's evidence for the commit-dialog case of BS 1 is thin (one
frame with a dim left end); Windows measured it and Linux hit-tested it. BS 4, added after the triage, was walked on
Windows only (the owner's choice), of `86e2032` and `9ebd391`.

## Step 0 — the repo-open gap, Windows — test-pc (session git-ui-win-vm)

- Build: `app-wide-fixes` `5a88649` (its code equals `52fd957`), `tauri build --no-bundle`, launched with
  `smoke-launch.ps1`. WebView2 154.0.4258.62, git 2.55.0.windows.5, Windows 11 Pro 26300. The store was backed up first
  and restored byte-exact after.
- Method: clicks over CDP on the toolbar's repo button, then the Recents item; times from the page's `performance.now()`
  (a capture-phase click listener and a MutationObserver on `document.body`). Two other tabs open each run, the
  target's tab closed first.
- Click → tab, ms, 15 runs: set A (the first harness) and set B (an updated one that also timed the overlay closing);
  the relaunch runs came last, with set B's harness:

  | Run | Set A | Set B | Medians |
  |---|---|---|---|
  | Small repo (s3, with s1 + s2 open) | 30.2 / 20.7 / 22.7 | 24.1 / 19.3 / 20.0 | 22.7 / 20.0 |
  | `perf-synth` warm | 24.2 / 25.5 / 22.7 | 26.6 / 22.9 / 23.7 | 24.2 / 23.7 |
  | `perf-synth`, first open after a relaunch | — | 32.7 / 26.7 / 32.0 | 32.0 |

- So the wait for the backend's answer is 19–33 ms, under the overlay's 150 ms delay: D changes nothing visible on
  Windows and stays as a guard. The relaunch runs aren't truly cold (the OS file cache stayed warm).
- The overlay was inserted in all 15 runs, in the same MutationObserver batch as the tab (today's code). Click →
  overlay gone (set B): small 49.3 ms median; `perf-synth` warm 449.7; after a relaunch 436.2 (one run 621.8).
- Backend log, the 9 `perf-synth` opens: opened repo 5–8 ms, watcher started 3.5–5 ms, labels computed 394–584 ms,
  refs read 1.25–2.32 s, slow status (entries=0) 250–334 ms in 4 of 9. No WARN or ERROR lines.
- The overlay closes once the grid is in (about 450 ms); the refs read runs on 0.9–1.9 s after it (S1).

  and a small repository (28 options, its list overflowing too); the Tab steps of `9ebd391` on `perf-synth` (692
  options) and another small repository (29 options):
  - A header click, a footer click then Esc, a right-click on a header, a press on a header dragged out over the

    list on a press; `86e2032`'s check covers it either way.
  - Tab, Shift+Tab, and three Tabs in a row: the focus stayed in the input, and typing "pus" filtered to 1 option. A
    header click after them still worked.
