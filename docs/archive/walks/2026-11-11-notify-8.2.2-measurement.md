# `notify` 8.2.0 against 8.2.2 on a mass delete — measurement, 2026-11-11

Step 2 of `docs/archive/plans/2026-11-11-notify-8.2.2-plan.md`. A standalone program, built once with `notify` 8.2.0
(what the app ships) and once with 8.2.2, watches a directory tree recursively the way the app does, deletes the tree,
and measures how long the watcher takes to report the next change. It ran on the Linux VM topher-ubuntu-vm (session
git-ui-lin), in that session's scratchpad; nothing in the repository was touched. **Result:** after the delete, 8.2.2
reported the next change after 3.7 s at 10 000 directories and 10.8 s at 30 000, against 1.3 s for 8.2.0 at both sizes,
with the watcher thread's CPU time almost equal to the wait. The owner kept the hold at 8.2.0 (N3, below).

## Setup

- Kernel 7.0.0-43-generic, 8 CPUs, 7376 MB of memory (3397 MB free, 5699 MB available). The VM had started about two
  minutes before the runs; load average 0.34 at the start and 1.38 at the end.
- The trees were on **tmpfs** (`/tmp`), not on a disk.
- rustc 1.99.0 (b940084d7 2026-09-28), `cargo build --release`.
- inotify limits, the VM's defaults: `max_user_watches` 65536, `max_queued_events` 16384, `max_user_instances` 128.
- Two cargo projects with the same `src/main.rs` (compared with `cmp`), their manifests differing only in the `notify`
  line. The locks: `notify` 8.2.0 and 8.2.2, `notify-debouncer-full` 0.7.0 in both.
- The watcher is set up as in `crates/git-core/src/watch.rs`: `new_debouncer_opt` with `NoCache`, a 250 ms debounce,
  `RecursiveMode::Recursive` on the root. The logger is capped at Info, the app's filter.

## A run

- A fresh root that holds only `top`, a tree shaped like an installed `node_modules`: `top/p<i>/d<j>/e<k>`, two small
  files in every directory, 10 directories per package. 1000 packages give 10 000 directories, 3000 give 30 000
  (`find -type d` counted 10 002 and 30 002 with the root and `top`).
- The program, one process per run: watch the root, run `rm -rf <root>/top`, then write a new `probe-<n>` file in the
  root once a second until a batch names one or 120 s pass.
- **Probe latency** is the time from `rm`'s return to the first probe batch. It includes the debouncer's own 0.25 to
  0.31 s. More than one probe written means nothing had arrived within a second: the first probe lost to a kernel queue
  overflow, or the watcher behind.
- **Thread CPU** is the on-CPU time of the thread `notify-rs inoti…` since the watch was set up, from
  `/proc/self/task/<tid>/schedstat`, read when the probe arrived and again 5 s later.
- **Events** are the debounced events handed to the program's handler, not inotify's own.
- Three runs per version and size, the versions alternating (8.2.0, 8.2.2, 8.2.0, …).

## What was measured

- **Every run of both versions overflowed the kernel's event queue** (a rescan event in each: one at 10 000, two at
  30 000). The app refreshes everything on that flag, in either version (read from `crates/git-core/src/watch.rs`, not
  part of the run).
- **8.2.0** reported the probe 1.26 to 1.30 s after `rm` in five runs and after 0.44 s in one. Its thread used 0.41 to
  0.51 s of CPU at either size.
- **8.2.2** reported the probe after 3.5 to 3.9 s at 10 000 directories and 10.7 to 11.6 s at 30 000. Its thread used
  3.3 to 3.6 s and 10.7 to 11.6 s of CPU, and no more in the 5 s after.
- **8.2.2 logged 2769 to 2817 Info lines per run,** about the same at both sizes.
- `rm` took the same time under both versions.

## What is reasoned, not measured

- **8.2.0's 1.3 s is mostly the probes' spacing.** Its first probe was lost while the queue was full; the second,
  written a second later, arrived after the debounce delay alone. The one run with 0.44 s is the first probe getting
  through.
- **8.2.2's thread was busy for the whole wait:** its CPU time almost equals the latency. The CPU count starts before
  `rm` and the latency includes the debounce delay: two offsets of 0.1 to 0.3 s each, which account for the small gap
  between the two. No profile or stack was taken.
- **The overflow capped 8.2.2's work.** 8.2.2 writes the line once for each descriptor a pass fails to remove
  (`inotify.rs:483`, `:490`): one per pass when the directories below were removed in earlier passes, more when their
  events were lost. So there were at most about 2 800 passes at either size, far fewer than directories, and the
  overflow, not the tree, set their number. The time still tripled with the tree: taking one line per pass, about 1.3 ms
  per pass over 10 000 watched paths and 3.8 ms over 30 000 (1.1 and 3.7 ms without the 0.4 to 0.5 s that 8.2.0 spends
  with no pass), which fits a pass that walks every watched path.
- **Without an overflow** (a delete slow enough for the watcher to keep up, or a raised queue) 8.2.2 would make one
  pass per deleted directory. At 3.8 ms a pass that is about one minute for 30 000 directories, since the list of
  watched paths shrinks as the delete goes on, and two minutes at most if it did not. An extrapolation.
- **What the runs do not cover:** one VM; tmpfs, not ext4; no app around the watcher; a root that holds only the tree,
  so fewer watched paths than a repository with its `.git` and sources beside it; three runs per cell.

## Not run

- **Set B,** the same 12 runs with `fs.inotify.max_queued_events` raised, which the plan asks for when runs overflow. It
  needs `sudo` on the VM, and the VM session did not run it on another session's word. The owner ruled to skip it (N4):
  it could only show a higher cost for 8.2.2. So the CPU times above are a lower bound on 8.2.2's cost, and the cost of
  a delete that does not overflow is only extrapolated (above).

## The rulings (the owner, 2026-11-11)

- **N3: the hold at 8.2.0 stays,** to reopen on a `notify` release without the per-removal pass or on the Windows race
  seen. Not taken: lifting to 8.2.2 through its own plan, which would bring the fix for a Windows stop race that 8.2.0
  has (the plan, "What 8.2.2 changes"), the Linux cost above, and on macOS a backend swap with no Mac to walk it on.
- **N4: Set B is skipped** (above).
- **N5: a report of the removal pass is drafted for the owner to read.** No issue on `notify-rs/notify` covers it
  (searched 2026-11-11). Its pull request 1074 ("skip unnecessary watch scans", merged 2026-11-05, on the 9.0 line)
  skips a scan only when a removal needs no recursive cleanup, and a removal that follows a delete event always asks for
  it. Posting the report is asked separately.

## Clean up

Both `target` directories and every tree deleted; `max_queued_events` still 16384 (never changed); no `notify-bench`
process left.

import os, sys
root, packages = sys.argv[1], int(sys.argv[2])
def mk(d):
    os.makedirs(d)
    for n in ("a.js", "b.json"):
        with open(os.path.join(d, n), "w") as f:
            f.write("x\n")
for i in range(packages):
    p = os.path.join(root, "top", f"p{i}")

    for j in range(3):

`src/main.rs`, run as `notify-bench <root> top <label>`; it prints one JSON line:

```rust
// Measures how far a recursive notify watch falls behind a mass delete.
// usage: notify-bench <root> <top-dir-name> <label>
//   <root> holds only <top-dir-name>, the tree to delete. Prints one JSON line.
use notify::{RecommendedWatcher, RecursiveMode};
use notify_debouncer_full::{new_debouncer_opt, DebounceEventResult, NoCache};
use std::collections::BTreeMap;
use std::path::PathBuf;
use std::sync::atomic::{AtomicU64, Ordering};
use std::sync::{Mutex, OnceLock};
use std::time::{Duration, Instant};

const DEBOUNCE: Duration = Duration::from_millis(250); // the app's, crates/git-core/src/watch.rs:29
const LIMIT: Duration = Duration::from_secs(120);

static LOGS: OnceLock<Mutex<BTreeMap<String, u64>>> = OnceLock::new();
static EVENTS: AtomicU64 = AtomicU64::new(0);
static RESCANS: AtomicU64 = AtomicU64::new(0);
static ERR_BATCHES: AtomicU64 = AtomicU64::new(0);
static T0: OnceLock<Instant> = OnceLock::new();
// Milliseconds since T0 at which the first probe batch arrived, plus one (0 = not yet).
static PROBE_AT: AtomicU64 = AtomicU64::new(0);

struct Counter;
impl log::Log for Counter {
    fn enabled(&self, m: &log::Metadata) -> bool {
        m.level() <= log::Level::Info
    }
    fn log(&self, r: &log::Record) {
        if !self.enabled(r.metadata()) {
            return;
        }
        let text = r.args().to_string();
        let head: String = text.chars().take(44).collect();
        let key = format!("{} {}", r.level(), head);
        *LOGS.get().unwrap().lock().unwrap().entry(key).or_insert(0) += 1;
    }
    fn flush(&self) {}
}

fn ms_since_t0() -> u64 {
    T0.get().unwrap().elapsed().as_millis() as u64
}

/// On-CPU nanoseconds of the thread whose name starts with `notify-rs inoti` (Linux cuts it to 15 bytes).
fn watcher_cpu_ns() -> Option<u64> {
    for entry in std::fs::read_dir("/proc/self/task").ok()? {
        let dir = entry.ok()?.path();
        let comm = std::fs::read_to_string(dir.join("comm")).unwrap_or_default();
        if comm.trim().starts_with("notify-rs inoti") {
            let stat = std::fs::read_to_string(dir.join("schedstat")).ok()?;
            return stat.split_whitespace().next()?.parse().ok();
        }
    }
    None
}

fn sysctl(name: &str) -> String {
    std::fs::read_to_string(format!("/proc/sys/fs/inotify/{name}"))
        .map(|s| s.trim().to_string())
        .unwrap_or_else(|_| "?".into())
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    let root = PathBuf::from(&args[1]);
    let top = root.join(&args[2]);
    let label = args.get(3).cloned().unwrap_or_default();

    LOGS.set(Mutex::new(BTreeMap::new())).ok();
    log::set_logger(&Counter).unwrap();
    log::set_max_level(log::LevelFilter::Info);
    T0.set(Instant::now()).ok();

    let handler = move |result: DebounceEventResult| match result {
        Ok(events) => {
            EVENTS.fetch_add(events.len() as u64, Ordering::Relaxed);
            for ev in &events {
                if ev.need_rescan() {
                    RESCANS.fetch_add(1, Ordering::Relaxed);
                }
                let probe = ev.paths.iter().any(|p| {
                    p.file_name()
                        .and_then(|n| n.to_str())
                        .is_some_and(|n| n.starts_with("probe-"))
                });
                if probe {
                    let _ = PROBE_AT.compare_exchange(0, ms_since_t0() + 1, Ordering::SeqCst, Ordering::SeqCst);
                }
            }
        }
        Err(_) => {
            ERR_BATCHES.fetch_add(1, Ordering::Relaxed);
        }
    };

    let mut debouncer =
        new_debouncer_opt::<_, RecommendedWatcher, NoCache>(DEBOUNCE, None, handler, NoCache::new(), notify::Config::default())
            .expect("debouncer");
    let w0 = Instant::now();
    debouncer.watch(&root, RecursiveMode::Recursive).expect("watch");
    let watch_ms = w0.elapsed().as_millis();
    let cpu_before = watcher_cpu_ns();

    let r0 = Instant::now();
    let status = std::process::Command::new("rm").arg("-rf").arg(&top).status().expect("rm");
    let rm_ms = r0.elapsed().as_millis();
    let rm_done = ms_since_t0();

    // One new probe file a second, in the root itself, until a batch names one.
    let mut probes = 0u64;
    let p0 = Instant::now();
    while PROBE_AT.load(Ordering::SeqCst) == 0 && p0.elapsed() < LIMIT {
        let _ = std::fs::write(root.join(format!("probe-{probes}")), b"x");
        probes += 1;
        let tick = Instant::now();
        while tick.elapsed() < Duration::from_secs(1) && PROBE_AT.load(Ordering::SeqCst) == 0 {
            std::thread::sleep(Duration::from_millis(10));
        }
    }
    let at = PROBE_AT.load(Ordering::SeqCst);
    let cpu_at_probe = watcher_cpu_ns();
    std::thread::sleep(Duration::from_secs(5));
    let cpu_5s_later = watcher_cpu_ns();

    let logs = LOGS.get().unwrap().lock().unwrap();
    let logs_json: Vec<String> = logs.iter().map(|(k, v)| format!("{:?}:{}", k, v)).collect();
    let ns = |v: Option<u64>| v.map(|n| n.to_string()).unwrap_or_else(|| "null".into());
    let delta = |a: Option<u64>, b: Option<u64>| match (a, b) {
        (Some(a), Some(b)) => (b.saturating_sub(a) / 1_000_000).to_string(),
        _ => "null".into(),
    };
    println!(
        "{{\"label\":{:?},\"rm_ok\":{},\"watch_ms\":{},\"rm_ms\":{},\"probe_latency_ms\":{},\"probes_written\":{},\
\"cpu_ms_to_probe\":{},\"cpu_ms_5s_later\":{},\"cpu_ns_before\":{},\"events\":{},\"rescans\":{},\"err_batches\":{},\
\"max_queued_events\":{:?},\"max_user_watches\":{:?},\"logs\":{{{}}}}}",
        label,
        status.success(),
        watch_ms,
        rm_ms,
        if at == 0 { "\">120000\"".to_string() } else { (at - 1).saturating_sub(rm_done).to_string() },
        probes,
        delta(cpu_before, cpu_at_probe),
        delta(cpu_before, cpu_5s_later),
        ns(cpu_before),
        EVENTS.load(Ordering::Relaxed),
        RESCANS.load(Ordering::Relaxed),
        ERR_BATCHES.load(Ordering::Relaxed),
        sysctl("max_queued_events"),
        sysctl("max_user_watches"),
        logs_json.join(","),
    );
}
```
