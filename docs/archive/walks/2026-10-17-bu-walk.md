## Seen on the way (outcomes: the owner's, 2026-10-17)

1. **Blame parent is dead on a commit's second and later hunks.** Predates this branch (same on 0.10.24). git
   `blame --porcelain` prints `previous` and `filename` only on a commit's first hunk group (verified locally with git
   2.55 too); the parser (`blame.rs`, the `Open` doc comment) reads them per hunk, so later hunks get `previous` =
   None, `orig_path` = None. Blame parent shows disabled with the wrong hint. A renamed file's later hunks would lose
   `origPath` (reasoned, not walked). **Fixed** in `af9fb5fa`, re-walked (row 10); the rename case by a parser test,
   since the fixture has no later commit-1 hunk in `r2.txt`.
2. **A drill-down's y isn't clamped to the receiving view's height.** Row 12's pane behind the window (y 340 in
   251 px) and row 14 (y 380 in 238 px) left the cursor line off-screen. **Fixed** in `8030582e`, re-walked (rows 12,
   14).
3. **Focus moved once, unexplained.** Right after the first click in row 1, focus went from the cursor row to the
   "Staged files" listbox between two CDP runs. No cause found; not seen again. **Deferred.**
4. **Row 14's wording:** the Stashes dialog's Blame toggle carries over the pane's on state. Fixed in the row text.
5. **Correction to the BW walk:** the Ctrl+Q that "didn't quit" was a driver mistake (`Control+q` sent a bare "q";
   `cdp.mjs` takes `Ctrl+q`). Not an app issue. **The BW records are corrected** in the records commit.
