## The ssh check (new in this gate)

1. `ssh://git@github.com/<a nonexistent owner>/nope.git`: the VM's agent (`gcr`) holds an ED25519 key GitHub
   accepts, so the server replies "ERROR: Repository not found." and the app shows toast "Operation failed —
   fatal: Could not read from remote repository.", exit 128 after 2.5 s. No login cause — correct, login succeeded;
   a missing repo gets the generic toast.
2. `ssh://<a nonexistent user>@github.com/…`: "Permission denied (publickey)" with the loaded key. Fetch dialog,
   03:44:16.30: `git fetch` plus `ssh` ran 16.368–18.006 (1.64 s); dock shows "exit 128 · 1.7s" with ssh's
   Permission denied line; toast "SSH key not accepted — Load your key into the agent (ssh-add), or add its public
   key to your account on the server". No hang. `setsid` confirmed: `git` and `ssh` ran in their own session
   (sid = git's pid, pgid same), no controlling tty; the app's own session was `dbus-run-session`'s. The remote was
   removed after. Used the real `~/.ssh`; `github.com` was already in `known_hosts`. Not tested: no key loaded at
   all (that would change the user's own session).
