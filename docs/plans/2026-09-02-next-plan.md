## A. Deferred features — each needs a new backend command
- **Hunk-/line-level Discard.** Only file-level `discard_paths` exists. Needs reverse-apply of the
  same patch `stage_hunks` / `stage_lines` build, against the working tree instead of the index
  (`git apply --reverse` without `--cached`, or libgit2 `apply` to the workdir). UI: the hunk /
  line buttons the DiffViewer already has, plus a native confirm — the disabled placeholders were
  removed in the review pass, so this is additive.
- **Settings screen.** The Settings button is disabled everywhere. Contents: git executable path
  (`set_git_path` + "Locate git…" already exist; Settings only exposes them), theme override (the
  toggle exists; Settings would add "follow OS" back), diff context lines and whitespace default.
  Persist through `lib/kv.ts`.
- **File-row context menu** in the commit panel: Stage / Unstage / Discard, Copy path, Open in
  editor, Reveal in folder. The row actions exist; the menu is wiring plus `reveal` / `open`
  commands (shell plugin, capability entry).
- **Per-file Ours / Theirs** for a conflicted file (`git checkout --ours|--theirs -- <path>` then
  stage). Sits beside the existing "Resolve in editor" note.
- **"Push after create" checkbox** in Create tag, reusing the push-tag op.
- **Mode (exec-bit) changes in hunk / line staging.** The patches carry no `old mode` / `new mode`
  lines, so a mode change stages whole-file only. Unix-only; not verifiable on the Windows dev box,
  so it waits for a Linux/macOS session.

## B. UX follow-ups (small, no backend)
- Tree view legibility in the commit lists (offered 2026-09-02, not chosen yet): indent guide
  lines per depth, and/or compact single-child folder chains (`examples / exclude / schema` as one
  row), and/or a wider indent than the 14px token for lists whose file rows carry no chevron.

## C. Performance — measure before touching
- **Watcher `NoCache`** (review P4): the debouncer caches file metadata; on huge trees that may cost
  memory. Measure on a `git/git` clone first.
- **Virtualized output dock** (review P5): the dock renders up to 50 ops × 5000 lines as plain
  DOM. Virtualize only if a long-running op's output is visibly slow to scroll.
- `status.rs` `git status --porcelain=v2 -z` fallback behind a flag, only if libgit2 status proves
  slow on very large trees (v1 accepted limit).

## D. Verification and release — needs machines we do not have
- Installer on a clean Windows 11 (no dev tools, no WebView2 preinstalled? — the NSIS bundle
  should fetch it).
- Linux (WebKitGTK) and macOS rendering: never seen; CI compiles only. Check fonts, scrollbars,
  the graph canvas, splitter hit areas, native menus suppression.
- macOS signing / notarization; `release.yml` has never run (no `v*` tag pushed).
- UI-vs-canvas comparison pass (v1 plan M6 leftover): screenshots of the real app against the
  screens canvas, one pass, fix what differs or update the canvas.
- Dogfooding against the real GitHub remote (`toperux/t4-git-ui`): fetch / push / tag push with
  credentials through GCM, a failed push, a cancelled fetch — the smoke test only uses local bare
  remotes.
